# Учебный проект GophKeeper

Клиент-серверная система для безопасного хранения конфиденциальной информации:

- текстовая информация
- пары логин/пароль
- данные банковских карт

Система обеспечивает надежное шифрование данных, синхронизацию между клиентами и поддержку оффлайн-режима работы.
Для взаимодействия используется протокол gRPC с возможностью включения TLS для безопасного соединения.

## Основные возможности

- **Хранение данных**: Поддержка текстовых данных, учетных записей (логин/пароль) и данных банковских карт, произвольное количество мета-информации в формате ключ-значение.
- **Безопасность**: Все данные шифруются на стороне клиента с использованием гибридного шифрования (RSA + AES).
- **Оффлайн-режим**: Клиент может работать без подключения к серверу, используя только приватный ключ. При подключении к серверу данные синхронизируются.
- **Синхронизация**: Данные синхронизируются между различными клиентами пользователя. Актуальность определяется по времени обновления с учетом разницы во времени между клиентом и сервером.
- **Авторизация**: Используется пара публичный/приватный ключ. Регистрация отправляет публичный ключ на сервер, а авторизация выполняется через подпись данных приватным ключом.
- **TLS**: Поддержка защищенного соединения между клиентом и сервером с использованием TLS-сертификатов.

## Архитектура системы

### Протокол
- **gRPC**: Для взаимодействия между клиентом и сервером используется протокол gRPC, обеспечивающий высокую производительность и строгую типизацию.
- **TLS**: Поддерживается защищенное соединение с использованием сертификатов (ca.crt для клиента, server.crt и server.key для сервера).

### Шифрование
- **Гибридное шифрование**:
    - Данные и мета шифруются на клиенте с использованием AES.
    - Для каждого секрета генерируется свой AES ключ, шифруется с помощью RSA и хранится на сервере вместе с данными.
- **Подпись запросов**:
    - Каждый запрос подписывается клиентом с использованием приватного ключа и временной метки (для защиты от атак воспроизведения).
    - Сервер авторизует запросы, проверяя подпись с помощью публичного ключа пользователя.

### Авторизация
- Каждый запрос содержит идентификатор данных (`ID`), идентификатор пользователя (`userID`), временную метку (`timestamp`) и цифровую подпись. Подпись формируется на основе всех отправляемых данных, включая `ID`, `userID` и `timestamp`. Сервер проверяет подпись с использованием публичного ключа пользователя. Допустимое расхождение времени в `timestamp` составляет 1 минуту для защиты от атак воспроизведения.
- **Регистрация**: Клиент отправляет публичный ключ подписанным запросом. В ответ сервер возвращает `userID`.
- **Логин**: Клиент отправляет fingerprint публичного ключа подписанным запросом. В ответ сервер возвращает `userID`.

### Синхронизация
- Данные синхронизируются между клиентами на основе времени обновления, если приходят данные с ранним временем обновления, то они отклоняются как сервером, так и клиентом (в случае клиента это означает, что секрет не синхронизирован с сервером и будет отправлен).
- Для учета возможных временных расхождений между клиентом и сервером система вычисляет смещение времени, используя формулу: `((receiveServerTime - startRequestTime) + (endRequestTime - responseServerTime)) / 2`.

## Сервер

Сервер отвечает за хранение зашифрованных данных и проверку подписей запросов. Основные компоненты:

- **База данных**: Используется PostgreSQL для хранения данных.
    - Таблица `users`:

  | Поле          | Тип         | Описание                   |
  |---------------|-------------|----------------------------|
  | `id`          | bigint      | Идентификатор пользователя |
  | `fingerprint` | varchar     | Отпечаток публичного ключа |
  | `public_key`  | text        | Публичный ключ             |
  | `created_at`  | timestamp   | Время записи               |
  | `updated_at`  | timestamp   | Время обновления           |

    - Таблица `secrets`:

  | Поле          | Тип         | Описание                             |
  |---------------|-------------|--------------------------------------|
  | `id`          | string      | Идентификатор секрета (можно менять) |
  | `user_id`     | bigint      | Идентификатор пользователя           |
  | `crypt`       | bytea       | Зашифрованный AES-ключ (RSA)         |
  | `meta`        | bytea       | Зашифрованные метаданные (AES)       |
  | `data`        | bytea       | Зашифрованные данные (AES)           |
  | `created_at`  | timestamp   | Время создания записи                |
  | `updated_at`  | timestamp   | Время последнего обновления          |


- **Логика работы**:
    - Хранит только зашифрованные данные, не имея доступа к их содержимому.
    - Проверяет подписи запросов для аутентификации и защиты от несанкционированного доступа.
    - Обеспечивает синхронизацию данных между клиентами на основе gRPC-stream.

## Клиент

Клиентская часть отвечает за шифрование, дешифрование и синхронизацию данных. Основные особенности:

- **Оффлайн-режим**: Клиент может работать без подключения к серверу, используя только приватный ключ.
- **Шифрование**: Все данные шифруются на стороне клиента до отправки на сервер. Поддерживает приватные ключи RSA, DSA, ECDSA и Ed25519 в форматах PKCS#1, PKCS#8, OpenSSL и OpenSSH.
- **Синхронизация**: При регистрации/логине/восстановлении соединения клиент автоматически синхронизирует данные с сервером.
- **Интерфейс**: Предоставляет пользовательский интерфейс (TUI), реализованный с использованием библиотек [bubbletea](https://github.com/charmbracelet/bubbletea) и [lipgloss](https://github.com/charmbracelet/lipgloss).

## Конфигурация

Система поддерживает несколько способов конфигурации:
- Аргументы командной строки
- Переменные окружения
- Файл `.env`
- Конфигурационный файл JSON

### Аргументы командной строки

#### Клиент

| Аргумент             | Описание                                                                 | По умолчанию         |
|----------------------|--------------------------------------------------------------------------|----------------------|
| `-c`<br/>`--config`  | Путь к конфигурационному файлу                                           | `config_client.json` |
| `-w`<br/>`--write`   | Записать конфигурационный файл при успешном завершении работы приложения | `false`              |
| `--addr`             | Адрес gRPC-сервера                                                       | `localhost:3200`     |
| `--log-level`        | Уровень логирования (от `-1` до `5`)                                     | `0`                  |
| `--log-outputs`      | Пути для вывода логов, разделенные запятыми                              | `client.log`         |
| `--private-key`      | Путь к приватному ключу (необязательно, можно указать в интерфейсе)      |                      |
| `--ca`               | Путь к сертификату CA (`./certs/ca.crt` для localhost)                   |                      |

#### Сервер

| Аргумент            | Описание                                                                 | По умолчанию         |
|---------------------|--------------------------------------------------------------------------|----------------------|
| `-c`<br/>`--config` | Путь к конфигурационному файлу                                           | `config_server.json` |
| `-w`<br/>`--write`  | Записать конфигурационный файл при успешном завершении работы приложения | `false`              |
| `--addr`            | gRPC-адрес хоста                                                         | `localhost:3200`     |
| `--log-level`       | Уровень логирования (от `-1` до `5`)                                     | `0`                  |
| `--log-outputs`     | Пути для вывода логов, разделенные запятыми                              | `stderr`             |
| `--dsn`             | Строка подключения к базе данных PostgreSQL                              |                      |
| `--cert`            | Путь к TLS-сертификату сервера (`./certs/server.crt` для localhost)      |                      |
| `--key`             | Путь к TLS-ключу сервера (`./certs/server.key` для localhost)            |                      |

### Пример конфигурации `.env` для клиента
```
ADDR="localhost:3200"
LOG_LEVEL=0
LOG_OUTPUTS="client.log"
PRIVATE_KEY_PATH=""
CA_PATH="./certs/ca.crt"
```

### Пример конфигурации `.env` для сервера
```
DB_PORT_EXTERNAL=5432
ADDR="localhost:3200"
LOG_LEVEL=0
LOG_OUTPUTS="stderr"
DSN="postgres://gophkeeper:wI94ZvRX0Ajt@localhost:5432/gophkeeper?sslmode=disable"
CERT_PATH="./certs/server.crt"
KEY_PATH="./certs/server.key"
```

### Пример конфигурационного файла JSON для клиента
```json
{
  "addr": "localhost:3200",
  "ca_path": "./certs/ca.crt",
  "log_level": 0,
  "log_outputs": [
    "client.log"
  ],
  "private_key_path": ""
}
```

### Пример конфигурационного файла JSON для сервера
```json
{
  "addr": "localhost:3200",
  "cert_path": "./certs/server.crt",
  "dsn": "postgres://gophkeeper:********@localhost:5432/gophkeeper?sslmode=disable",
  "key_path": "./certs/server.key",
  "log_level": 0,
  "log_outputs": [
    "stderr"
  ]
}
```

## Установка и запуск

Используется GitHub Workflows для автоматизации сборки и выпуска бинарных файлов. Процесс сборки настроен в файле `.github/workflows/build.yml`.

Бинарные файлы для платформ Windows, macOS или Linux и все необходимое для запуска можно скачать на странице [**Releases**](https://github.com/korobkovandrey/gophkeeper/releases).
